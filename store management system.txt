# 📘 1. SYSTEM OVERVIEW

## System Name:

**Integrated Store & Requisition Management System (ISRMS)**

## Objective:

To digitize and automate:

* Stock recording (Telecard / Stock Register)
* Receiving of goods (SRA)
* Issuing of goods (Requisition → Issue)
* Approval workflows (multi-level signatures)
* Real-time inventory tracking with alerts

---

# 🧩 2. CORE SYSTEM CONCEPT

The system merges:

* **Telecard (item ledger)**
* **Stock Register**

👉 Into a **single real-time inventory ledger system**

Each item will have:

* Running balance
* History of inflow (receipts)
* History of outflow (issues)

---

# 🧱 3. SYSTEM MODULES

---

## 📦 A. Item & Inventory Module

### Purpose:

Central registry of all store items.

### Features:

* Add/Edit/Delete items
* Item categories (furniture, consumables, etc.)
* Units (pieces, bags, etc.)
* Minimum & maximum stock levels
* Real-time balance tracking

### Behavior:

* Automatically updates on:

  * Receiving (increase)
  * Issuing (decrease)

---

## 📥 B. Receiving Module (SRA – Stores Received Advice)

### Workflow:

1. Supplier delivers goods with:

   * Bill
   * Waybill

2. Storekeeper records receipt in system

3. System generates **SRA (digital)**

---

### Approval Flow (STRICT SEQUENCE):

```text
Storekeeper → Internal Auditor → Principal
```

### Logic:

* Storekeeper inputs received items
* System notifies Internal Auditor
* Auditor verifies and signs digitally
* System notifies Principal
* Principal signs
* Only AFTER all signatures:
  👉 SRA becomes printable

---

### Features:

* Auto SRA number generation
* Multi-signature workflow
* Printable SRA document (PDF)
* Audit trail of approvals

---

## 📤 C. Requisition Module

### Users:

* Departments / Requesters (limited access)

### Features:

* Create requisition:

  * Select items
  * Enter quantities
* Submit request

---

### Approval Workflow:

```text
Requester → Principal → Storekeeper
```

### Logic:

* Requester submits requisition
* Principal receives notification
* Principal approves/rejects
* Storekeeper is notified after approval

---

## 📦 D. Issue Module (Storekeeper)

### Process:

1. Storekeeper views approved requisitions
2. Checks available stock
3. Enters:

   * Quantity issued
4. System:

   * Deducts from inventory
   * Records transaction

---

### Roles in Issue:

* **Issuer** → Storekeeper
* **Receiver/Collector** → Requesting user

---

### Features:

* Partial or full fulfillment
* Digital acknowledgment (receiver name)
* Auto-update inventory
* Issue records (linked to requisition)

---

## 📊 E. Inventory Ledger (Telecard Equivalent)

### Purpose:

Digital replacement of:

* Telecard
* Stock register

---

### For EACH item:

* Opening balance
* Quantity received
* Quantity issued
* Running balance

---

### Features:

* Real-time updates
* Transaction history
* Filter by date range
* Export/print ledger

---

## 📈 F. Reporting Module

### Reports:

* Stock balance report
* Item ledger report
* Issued items report
* Received items report
* Low stock / out-of-stock report

---

### Special Feature:

* “Click of a button” → generate full stock position

---

## 🔔 G. Notification & Alert System

### Triggers:

* Requisition submitted → notify Principal
* Requisition approved → notify Storekeeper
* SRA created → notify Auditor
* Auditor signs → notify Principal
* Low stock → notify Storekeeper

---

## ⚠️ H. Stock Control System

### Features:

* Minimum stock level
* Maximum stock level

### Alerts:

* Low stock warning
* Out-of-stock alert

---

## 👤 I. User & Role Management

### Roles & Permissions:

| Role                   | Permissions                        |
| ---------------------- | ---------------------------------- |
| Admin                  | Full system control                |
| Storekeeper            | Manage inventory, SRA, issue items |
| Internal Auditor       | Verify and sign SRA only           |
| Principal              | Approve requisitions & SRA         |
| Requester (Department) | Create requisitions only           |

# 📘 INTEGRATED STORE & REQUISITION MANAGEMENT SYSTEM (ISRMS)

## SYSTEM DOCUMENTATION

---

# 1. TERMS OF REFERENCE (ToR)

## 1.1 Background

The current store management process relies on manual documentation such as Stores Received Advice (SRA), requisition forms, and stock registers (telecards). This approach leads to inefficiencies, delays, lack of real-time visibility, and limited accountability.

## 1.2 Objective

To design and implement a digital system that automates and integrates:

* Inventory management
* Requisition workflows
* Receiving and issuing processes
* Multi-level approval and verification
* Real-time stock tracking and reporting

## 1.3 Purpose

The system will:

* Replace manual records with a centralized digital platform
* Improve transparency and accountability
* Provide real-time stock visibility
* Enforce approval workflows
* Reduce errors and fraud

---

# 2. SCOPE OF THE SYSTEM

## 2.1 In Scope

The system shall:

* Manage all store items (add, update, track)
* Digitize Stores Received Advice (SRA)
* Enable requisition submission and approval
* Facilitate item issuing based on approved requisitions
* Maintain a real-time inventory ledger (telecard equivalent)
* Support multi-user roles with defined permissions
* Generate reports and alerts

## 2.2 Out of Scope

* Supplier procurement management (beyond receiving)
* Financial accounting integration (optional future phase)
* External payment systems

---

  * Admin
  * Storekeeper

* Add, edit, delete items

  * Minimum and maximum stock levels

2. Internal Auditor verifies and signs

### Features:

* Requesters submit item requests

* Submit requisition

### Workflow:

1. Requester submits requisition
2. Principal reviews and approves/rejects
3. Storekeeper receives approved request

---

## 3.5 Issue Module

### Features:

* Storekeeper views approved requisitions
* Confirms available stock

### Roles:

* Issuer: Storekeeper

### Behavior:

* Deduct issued quantity from inventory
* Allow partial or full fulfillment
* Record receiver details

## 3.6 Inventory Ledger (Telecard)

### Features:

* Maintain real-time ledger per item
* Record:

  * Quantity received
  * Quantity issued

## 3.7 Reporting Module

### Reports:

* Current stock levels
* Item transaction history

* Low stock alerts

| Field     | Type         | Description         |

## 6.3 Inventory Ledger Table

| Field            | Type         | Description               |
| ---------------- | ------------ | ------------------------- |
| id               | Integer (PK) | Unique identifier         |
| item_id          | FK           | Reference to item         |
| transaction_type | String       | RECEIVE / ISSUE           |

| Field              | Type         | Description        |
| ------------------ | ------------ | ------------------ |

| Field    | Type         | Description       |
| -------- | ------------ | ----------------- |

---

## 6.6 Requisitions Table

| Field        | Type         | Description                   |
| ------------ | ------------ | ----------------------------- |

## 6.7 Requisition_Items Table

| Field              | Type         | Description              |
